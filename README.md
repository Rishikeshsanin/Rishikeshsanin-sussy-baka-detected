# Sussy Baka Detected

**Think of someone. Don't snitch. Let the detector cook.**

Sussy Baka Detected (SBD) is an Akinator-inspired AI guessing game for real people and fictional characters. The player answers **Yes**, **No**, **Probably**, **Probably not**, or **Don't know** while a hybrid deduction engine narrows the suspect pool and tries to identify the person in roughly twenty questions.

The meme personality is intentional. The deduction system underneath it is not a meme.

> SBD is an independent project with original branding and implementation. It is not affiliated with Akinator.

## Why V2 exists

The legacy prototype used an LLM as almost the entire deduction engine: it invented the next question, candidate shortlist, and confidence value. That produced a polished demo but an unreliable game.

V2 changes the architecture:

- a curated seed knowledge base supplies structured candidate traits;
- candidate probabilities are updated from every answer;
- the next local question is selected by expected information gain;
- rejected guesses are removed from the posterior;
- LLMs are used as a long-tail/recovery layer instead of the only brain;
- LLM self-reported confidence is capped by server-side evidence-depth rules before the normal guess policy can accept it.

The exact V1 snapshot is preserved on the [`legacy-v1`](../../tree/legacy-v1) branch.

## Current features

- Adaptive game length: easy cases may finish early; difficult cases can continue up to a 30-question safety ceiling.
- Five answer strengths that preserve uncertainty instead of forcing every clue into a boolean.
- Bayesian-style weighted candidate ranking over a curated real + fictional seed pool.
- Entropy/information-gain question selection for deterministic local turns.
- Hybrid long-tail reasoning through Gemini, local Ollama, or the deterministic mock provider.
- Server-side confidence calibration for LLM guesses.
- Wrong-guess recovery without restarting the game.
- Duplicate-question and rejected-guess protection.
- Undo, restart, answer history, retry, win, and give-up flows.
- Versioned local persistence so active games survive refreshes safely.
- Contextual meme reactions based on game state instead of random meme spam.
- Responsive mobile/desktop layout, keyboard controls, focus states, reduced-motion support, and semantic live status.
- Dynamic favicon and social preview generated by Next.js.
- CI quality gate for typecheck, tests, lint, and production build.

## Game personality

The interface deliberately reacts to the deduction state:

```text
low signal      -> bro could literally be anybody 💀
mid signal      -> hold up... I'm seeing the vision 👀
high signal     -> nahhhh I might know bro
wrong guess     -> I sold once. It will NOT happen again.
correct guess   -> SUSSY BAKA DETECTED / CAUGHT IN 4K.
give up         -> I'm cooked. 💀
```

These reactions are presentation only. Candidate probabilities and question selection stay independent of the meme layer.

## Architecture

```text
Browser
  |
  |  answers + game state
  v
POST /api/game/turn
  |
  +-- request limits + Zod validation
  +-- duplicate / guess-policy guardrails
  +-- timeout + safe error mapping
  |
  v
HybridProvider
  |
  +--> Candidate Engine
  |      +-- curated seed profiles
  |      +-- weighted answer likelihoods
  |      +-- posterior ranking
  |      +-- rejected-candidate filtering
  |
  +--> Question Engine
  |      +-- trait question bank
  |      +-- binary entropy
  |      +-- best information-gain split
  |
  +--> Confidence Engine
  |      +-- posterior probability
  |      +-- candidate separation
  |      +-- evidence depth
  |      +-- LLM confidence cap
  |
  +--> Long-tail fallback
         +-- Gemini
         +-- Ollama
         +-- deterministic MockProvider
```

The common path can therefore choose questions without paying for an AI request. The LLM becomes useful when the local shortlist is weak, exhausted, or a guess is rejected.

## Getting started

### Requirements

- Node.js 20.9+ (CI currently uses Node 22)
- npm
- Gemini API key only if you want Gemini long-tail recovery
- or a local Ollama model if you prefer local inference

### Install

```bash
npm install
```

Create a local environment file:

```bash
# macOS / Linux
cp .env.example .env.local

# Windows PowerShell
Copy-Item .env.example .env.local
```

### Provider options

#### Mock — zero credentials

```dotenv
AI_PROVIDER=mock
```

The candidate/question engine still runs normally. If the game needs long-tail fallback, the deterministic mock provider is used.

#### Gemini

```dotenv
AI_PROVIDER=gemini
GEMINI_API_KEY=YOUR_KEY
GEMINI_MODEL=gemini-3.6-flash
```

The key is server-side only. Never prefix it with `NEXT_PUBLIC_`.

#### Ollama

```dotenv
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=YOUR_INSTALLED_MODEL_TAG
```

### Run locally

```bash
npm run dev
```

Open `http://localhost:3000`.

### Full verification

```bash
npm run check
```

Equivalent individual commands:

```bash
npm run typecheck
npm test
npm run lint
npm run build
```

## Security and privacy

- Provider keys exist only in server-side environment variables.
- The browser never calls Gemini or Ollama directly.
- `.env*` files are ignored except the safe `.env.example` template.
- Request bodies are size-bounded and schema-validated.
- Structured model responses are schema-validated again at runtime.
- Raw provider errors, prompts, stack traces, and secrets are not returned to players.
- Duplicate requests for the same in-flight game are rejected.
- Active game state is stored locally in the browser; V2 has no accounts or cloud profile database.
- Candidate hypotheses remain hidden from the player until an actual guess is made.

## Guess confidence policy

SBD does not treat a language model saying `0.99` as a genuine 99% probability.

For local candidates, game confidence is derived from the posterior distribution, the lead over the runner-up, structured evidence depth, and uncertainty penalties. For long-tail LLM guesses, self-reported confidence is capped by evidence depth and penalized after rejected guesses. The existing server guess guard then decides whether the result may be shown or whether another question is required.

## Roadmap

V2 establishes the reliable core. Future expansion can include:

- larger automatically maintained Wikidata-backed candidate knowledge;
- richer candidate-specific attributes and entity aliases;
- measured Top-1 / Top-3 benchmark suites;
- optional anonymous failure-learning pipeline with explicit privacy boundaries;
- game modes and themed candidate packs;
- shareable result cards and session stats;
- distributed production rate limiting if traffic requires it.

## Development philosophy

**Quality > quantity.**

The goal is not to claim an infinite candidate database. The goal is a guessing game whose architecture can explain why it asks each local question, degrades safely when AI services fail, and remains fun enough that the engineering does not feel like homework.
